ISSUE FOUND AND FIXED
  The GLM-5.3 endpoint always produces native reasoning. It ignored all of:
  reasoning.enabled=false, chat_template_kwargs.enable_thinking=false,
  chat_template_kwargs.thinking=false, thinking.type=disabled, reasoning_effort=none.
  With the original token limits (plan 400, channel 200, act 300) the reasoning used the
  whole allowance and the JSON answer was empty: 0/4 valid in testing.
  Fix: config/models.yaml, glm.max_tokens_multiplier 1 -> 20. After the fix: 8/8 valid.

COST WARNING (still open)
  With reasoning forced on, GLM used ~1,670 output tokens per call on average (range 459-2,429 in
  this round; up to ~6,000 in probes), against the ~50-150 a non-reasoning call would need.
  The solo grid (~2,700 agent calls) would use roughly 5-6M tokens, more than the
  default budget.max_total_tokens of 4M, so the run would stop partway.
  The proper fix is server-side: disable thinking by default in the Modal deployment's
  chat template, then set the multiplier back to 1.
